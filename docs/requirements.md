# わくわくフォニックス 要件定義書

版：1.0／作成日：2026年11月1日（日本時間）

**2026-11-11追補（最新のユーザー指示）:** 自動発音評価を科学的・技術的に十分検証できない場合は、録音と聴き比べにとどめる。下記の旧「両評価方式が初期版に必須」という範囲は、この条件付き方針に更新する。発音モデル導入、児童音声の外部送信、新しい有料サービス、教材全体の変更は比較案を提示して承認を得る。[現状監査](audit-summary.md)、[発音評価比較](pronunciation-evaluation-options.md)、[変更の承認対象](approval-decisions.md)を優先して参照する。未検証の機能を実装済み／効果確認済みとは扱わない。

本書は、保護者との対話で決まった内容と、残りを設計判断で補った内容を統合した要件定義である。アプリの実装、外部サービスの契約、教材の採用、実機検証は行っていない。要件を定めたことと、その実現性・品質を検証したことを区別する。

## 1. 目的と成功の定義

6歳・9歳の子どもが、それぞれのタブレットで一人で遊びながら、文字と音の関係を学び、習った規則で読める初見の英単語を読む力、音を聞き分ける力、発音を改善する力を育てる。

「初めて見る単語を読める」の対象は、学習済みの文字・綴りと規則で解読できる単語とする。英語の例外的な綴りを含むあらゆる単語が読めることは約束しない。

成功は次の観点で確認する。

- **自立操作：** 初回の保護者による設定後、両方の端末で、子どもが説明音声・ヒントを使って1レッスンを完了できる。
- **学習の転移：** 練習に使った単語だけでなく、同じ規則を使う未練習の単語でも改善が見られる。
- **聞き分け：** 同じ音声ファイルの暗記に依存せず、別の収録例でも対象音を選べる。
- **発音練習：** 毎回、お手本を聴き、声を出し、必要なら聴き比べる機会がある。自動評価の点数を学習効果そのものと扱わない。
- **継続しやすさ：** 通常の1レッスンは3〜5分を目安に完結し、間違いや判定不能で冒険が止まらない。

家庭の2人による試用は操作性と個別の学習変化を確認するために行う。2人の結果だけで、一般の子どもへの教育効果や発音評価精度を証明したと主張しない。

## 3. 本対話での決定と設計判断

### 3.1 保護者が決定した事項

- フォニックスを中心に、読む・聞き分ける・発音する力を育てる。
- 短いお試しクイズで開始地点を決める。
- 決まった順番で冒険し、進むと行ける場所が増える。
- 毎回、最初に1〜2問の復習を入れる。
- 毎回少しずつ発話練習を入れる。
- 間違えたらお手本と一緒に練習して先へ進み、後から復習する。
- 発音チェックの再挑戦は1回まで案内し、その後は先へ進める。
- オフラインでも限定的な発音自動チェックを行いたい。
- オンラインでは具体的な改善点を伝える。音声送信は、利用条件と費用を確認して保護者が有効にした場合だけ認める。
- 発音チェックは短い単語に加え、単独の音も対象に含める。
- 初期版の学習範囲はサイレントe・代表的な母音字の組み合わせまで。
- 動物を仲間にし、一緒に冒険する動物を選び、お世話もできる。
- 家庭で試してから、将来一般公開する。

### 3.2 本書で補った決定

- IPAは任意の「音の図鑑」で提供し、冒険の進行条件にしない。
- レッスン完了で次へ進める。島の最後には確認問題を置くが、不合格によるロックはしない。
- 動物・ごはんは練習の完了で獲得する。発音の推定精度や点数で報酬を減らさない。
- お世話は任意とし、未ログインによる病気、離別、アイテム没収は設けない。
- 発音評価の数値点は子どもに表示しない。根拠のある短い助言を1つずつ示す。
- オンライン評価は初期状態で無効。使えないときもオフラインの学習を継続する。
- 家庭版では課金、広告、SNS、ランキング、プッシュ通知、外部の行動分析SDKを入れない。
- 初期のオンライン評価費用の設計上限は、2端末合計で月1,000円相当を初期値とする。実際の料金・提供条件を確認してから採用し、本書によって有料契約や支出を開始しない。

## 5. 学習設計と教材範囲

### 5.1 共通原則

- アルファベットの名前と、文字が単語の中で表す音は別の再生ボタンと説明で示す。
- 文字名を暗記し終えるまで単語学習を待たせない。習った音から、早期に短い単語の結合を始める。
- 大小文字を対応付けて教えるが、単語は小文字を基本とする。どちらの文字で苦手かを記録する。
- 日本語のカタカナを発音の正解として表示しない。日本語では口の動き・息・声の出し方を説明する。
- 1レッスンの新出内容は原則1〜2種類の文字と音の対応までにする。
- 読む問題では、必要な綴り・規則を既に学んでいる単語を使う。
- 単語の意味は絵と短い日本語で支える。読解の確認中は絵による推測を避け、解答後に意味を示す。
- /p/、/t/などに不要な母音を足さない。伸ばせる音と、短く出す破裂音の見せ方・音源を分ける。
- xの/ks/、quの/kw/のような複数音の組み合わせを「1文字・1音」と説明しない。
- 「長母音」は単に音を長く伸ばす指示にしない。短母音との音質の違い、二重母音の動きを教える。

### 5.2 コース構成

初期版の制作単位は10島、各島6レッスンと1確認レッスン、計70レッスンとする。単純な反復だけで数を満たさず、下表の内容を割り当てる。教材試用で分割・統合が必要になった場合も、必須範囲は維持する。

| 島 | 新出内容・主な到達点 |
| --- | --- |
| 1 | s, a, t, p, i, n。基本の文字と音、習った音の結合を始める |
| 2 | m, d, g, o, c, k。CVC型の短い単語と音の分解を増やす |
| 3 | e, u, b, h, f, l。5つの短母音をそろえ、母音の聞き分けを始める |
| 4 | r, j, v, w, y, z。基本子音を広げ、/ɹ/と/l/などを聴き比べる |
| 5 | x, qu。26文字の抜け、大小文字、結合・分解をまとめて確認する |
| 6 | sh, ch, 無声th、有声th、ng、ck。複数の文字が表す音を学ぶ |
| 7 | st, sp, bl, plなどの語頭、nd, ntなどの語末の子音連結。音を省かずにつなぐ |
| 8 | a_e, i_e, o_e, u_e。cat/cape型などの対比からサイレントeを学ぶ |
| 9 | ai/ay, ee/ea, oa/owの代表的な読み方。cake/rainのように同じ音の別の綴りも知る |
| 10 | 既習規則の混合、似た音、未練習語への応用、苦手分野の復習 |

c/gの初期の読み方、y、u_e、ea、owなどは、採用する読み方と例外の扱いを教材データで明示する。たとえばowは初期には/oʊ/の用例を扱い、cow型まで同じ規則と説明しない。u_eは/ju/と/u/の違いを音源に合わせて説明し、無条件の単一規則にしない。

島ごとの単語は原則12語以上、コース全体で重複を除いて120語以上を準備する。そのうち30語以上は通常練習に出さない確認用語として確保し、必要な綴りを学んだ後にのみ使う。基本例はcat、dog、ship、chip、cake、rainなどとするが、収録前に綴り・音・学習順序・意味の適切さを確認する。

同じ語を別の収録で聴ける教材を設ける。一般公開までには聞き分けの主要問題を複数話者で確認し、声の高さや音量だけで正解が分からないようにする。

### 5.3 IPAと発音図

- IPAは「音の図鑑」で任意に表示する。通常の冒険では記号の暗記を求めない。
- 学習中の音から図鑑を開ける。IPAを隠す保護者設定を用意する。
- 米語の広い音素表記を教材共通の基準とし、下表の表記規約を使う。音声の細かな異音を全て記号化する狭い表記は初期版に使わない。
- 記号、音源、口・舌・唇の説明を照合し、音源に合わない表記を掲載しない。方言による許容差も教材メタデータに持たせる。
- 対象音には正面図または断面図と短い説明を用意し、必要な音には両方を示す。静止図を基本とし、動きが理解に役立つ音だけ簡単なアニメーションを加える。
- 解剖学的な正確さを保ちつつ、6歳にも理解できる指示にする。専門用語だけの説明は避ける。

| 表記項目 | 初期版の規約 |
| --- | --- |
| 5つの短母音 | a /æ/、i /ɪ/、o /ɑ/、e /ɛ/、u /ʌ/を基本例とする。単語の方言差は音源と照合する |
| 母音字の代表音 | a_e・ai・ay /eɪ/、i_e /aɪ/、o_e・oa・ow /oʊ/、ee・代表的なea /i/、u_e /ju/または/u/ |
| 長さ記号 | この米語の広い表記では/i/・/u/を使い、/iː/・/uː/と混在させない |
| r・y・jの代表音 | r /ɹ/、y /j/、j /dʒ/。文字の名前とは別に扱う |
| 複数字の代表音 | sh /ʃ/、ch /tʃ/、無声th /θ/、有声th /ð/、ng /ŋ/、ck /k/ |
| 複数音の綴り | x /ks/、qu /kw/は音の並びとして示し、1音素とは数えない |

これは各綴りの全ての読み方の一覧ではない。参照辞書の記号をそのまま混在させず、採用規約へ照合する。辞書の文章・音源を利用する場合は権利条件も確認する。

## 6. 初回体験・1回の学習・進行

### 6.1 初回設定とお試しクイズ

保護者が音量、ニックネーム、マイク利用、オンライン評価の可否を設定する。オンライン評価を無効にしたまま開始できる。マイク権限は実際に録音するときに求め、拒否しても他の機能は使える。

お試しクイズは2〜3分を目安に最大12問。文字名の知識だけでなく、大小文字、文字と音、短い単語の結合を段階的に確認する。新しい記号や長い日本語を読ませない。

文字名を知っていることや、既知語を1つ読めたことだけで先の島を習得済みにしない。連続した前提技能が確認できる最も早い未習得部分を開始地点として提案する。判定が曖昧な場合は短い導入・復習を勧める。保護者は開始地点を変更でき、確認できなかった技能は「未確認」として残す。

発音の自動評価結果は初期配置の必須条件にしない。診断をスキップした場合は島1から始める。

### 6.2 標準レッスン

| 順序 | 体験 | 時間の目安 |
| --- | --- | --- |
| 1 | 苦手・復習予定から1〜2問。最初の回は既習確認や導入に置き換える | 30〜45秒 |
| 2 | 仲間の動物と、新しい音・文字・口の動きを確認 | 30〜45秒 |
| 3 | 聞き分け、文字選択、組み立てなど3〜4問 | 60〜90秒 |
| 4 | 単独音または短い単語を1〜2回まねる。録音・助言・必要なら再挑戦 | 30〜60秒 |
| 5 | ごほうびを受け取り、お世話するか終了する | 15〜30秒 |

時間は目安とし、強制カウントダウンや時間切れの失敗は設けない。録音やお世話を繰り返すと5分を超えることは許容する。レッスン本体と任意のお世話時間を履歴上で区別する。

### 6.3 間違い・進級・復習

- 誤答時は選んだ音と正解の音を比べ、ヒントと一緒に1回練習して先へ進める。同じ問題を正解するまで繰り返させない。
- 通常レッスン完了で次を解放する。確認レッスンも、解説まで終えれば次の島へ進める。
- 既に開いた島は何度でも遊べる。初期診断による開始地点より前の島も遊べる。
- 島の確認は原則5問。既習内容、未練習語、聞き分けを組み合わせる。確認後に練習を案内するが、追加練習は進級の強制条件にしない。
- 間違えた技能は同じ回の後半または次の回で復習する。正解した技能は、次の学習日、約3日後、約7日後を初期の復習間隔とし、結果で調整する。
- 復習がたまっても冒頭は最大2問とし、未消化分を次回に回す。未学習内容の復習は出さない。
- 録音を避けたいとき、静かな場所で使えないとき、マイクが使えないときは発話部分をスキップできる。発話を実施済みとは記録しないが、レッスン完了を妨げない。

履歴では「触れた」「練習中」「定着の目安」を区別する。「定着の目安」は、同じ技能について別の学習回にまたがる直近5問の独力での初回解答が4問以上正解し、文字→音と音→文字の両方向を含む場合の表示とする。ヒント後の解答、同一問題の即時再挑戦、録音しただけの回数は、この判定の正解数に入れない。

正答率は最初の独力解答を母数とし、スキップ・判定不能・未実施は分ける。未練習語の選択問題は読みに関する間接的な指標であり、実際の音読能力と同一視しない。家庭試用では別途、保護者が少数の未練習語の音読を観察し、事前と事後を比較できる手順を用意する。

## 7. クイズ・操作・アクセシビリティ

- 問題種別は、音→文字、文字→音、音→単語、似た音の聞き分け、音の結合・分解、文字の並べ替え、穴埋めとする。
- 語彙の意味を問う問題と、文字から音を読む問題を混同せず、履歴でも区別する。
- 音だけでは一意に決まらない綴りや同音語を、単一正解の選択肢として並べない。同じ/k/のcとk、同音語、複数の母音の綴りなどは、文脈・候補の制約・許容解の設定で公平にする。
- 音声問題の選択肢は音量、無音の長さ、再生順などに正解の手掛かりを持たせない。
- 最小対立語は意味の分かりやすさと学習済み綴りを確認して採用する。未習得綴りが必要なら、文字を読ませる課題から分ける。
- 組み立てはタップで配置する操作を基本にする。ドラッグも提供する場合、タップだけで同じ課題を完了できるようにする。
- 操作対象は原則48dp以上。正誤や状態を色だけで区別しない。
- 子ども向けの操作案内は短い文章と同梱音声で提示する。音声案内は再生・停止できる。
- BGM・効果音・教材音声を別に調整でき、教材音声と録音中はBGMを抑制または停止する。口の動きは自動再生を止められる。
- 録音開始は見て分かる表示と合図を使い、お手本の再生と重ねない。短い発話を切り捨てないよう録音前後の余裕を設ける。

## 8. 発音練習・自動フィードバック

### 8.1 共通動作

お手本を聴く→自分で発音・録音する→必要なら聴き比べる→短い助言を見る、の順で進める。通常速度と、音程を維持したゆっくり再生を用意する。ただし破裂音など、速度変更で不自然になる素材には適用せず、必要なら別収録を使う。

初回に改善点が見つかった場合、再挑戦は1回まで案内する。自動評価による再挑戦は最大2録音で終え、以後は先へ進む。自由練習は別に何度でも行える。

録音できたこと、発話したこと、意図した単語と認識されたこと、発音が適切だったことは別の状態として扱う。音量や録音時間だけで「正しく言えた」と判定しない。

### 8.2 オフライン評価

端末内で、あらかじめ分かっている出題音・単語に対する限定的な音の比較を行う。汎用的な自由発話認識は初期要件にしない。

- 無音、短すぎる発話、過大入力、強い雑音を区別し、適切なら「声がよくきこえなかったよ」などと案内する。これは発音の正誤判定ではない。
- 検証できた音・対立についてのみ、実際の音の違いに基づく助言を出す。最初の技術検証候補は、伸ばして発音できる/s/と/ʃ/の単独音、および同じ対立を含む短い単語とする。
- 音のチェックができることを全コース対応と誤解させない。教材データに対応対象と精度条件を持たせる。
- 対象外や低い確信度の場合は「この音はお手本とききくらべてみよう」とし、確かな正誤を示さない。
- 単語全体や全音素の正確さを、1つの音だけの検出で合格としない。
- 音量確認だけを「限定的な発音自動チェック」の達成とは扱わない。単独音と短い単語の両方について、少なくとも1種類の実際の音の対立を区別できることが初期版の完成条件である。

Fire両実機で条件を満たす評価手法が得られなければ、この要件は未達のまま残す。録音・聴き比べだけの版を中間試作として出すことはできるが、本書どおりの初期版完成とはしない。端末内判定を外部送信で代替しない。

### 8.3 オンライン評価

保護者が利用を有効にしたとき、対象語・音の発音評価を行う。利用には通信と端末登録が必要だが、子どもの個人アカウントは作らない。

- 単語全体の認識結果だけでなく、音の省略、別の音への置き換え、余分な音などについて根拠が得られる方式を選ぶ。
- 「最後の音も出してみよう」「くちびるを少し丸くしてみよう」など、短く実行できる助言を最大1つ表示し、お手本と図に戻れるようにする。
- 子どもの声、単独音、米語の自然な発音変異への対応を検証する。単語用APIが単独音を正しく評価できるとは仮定しない。
- 技術検証を通過した対象について評価する。通過していない音・単語は聴き比べに切り替え、評価できたようには表示しない。
- 助言は、検証済みの評価結果と教材テンプレートの対応から生成する。汎用生成AIが録音の特徴を推測して自由に指摘する方式は初期版に使わない。
- 米語で許容される語末子音の未開放などを、単純に「最後の音がない」と誤判定しない。
- 子どもには点数、順位、「下手」などの表現を出さない。高い確信度で一致した場合だけ、対象を限定して肯定的に伝える。

通信が切れた場合、オンライン評価の上限に達した場合、サービスが応答しない場合は、オフライン処理または聴き比べへ戻る。再送を子どもに強制せず、同じ録音を無制限に送らない。オンライン評価待ちだけで8秒を超えない設計とし、超えたら学習を続けられる状態に戻す。

### 8.4 結果データの区別

評価結果は、少なくとも次を区別する。

| 状態 | 意味・表示 |
| --- | --- |
| 未実施 | スキップ・録音なし。未練習として記録 |
| 録音品質不足 | 無音・雑音など。発音の間違いとは記録しない |
| 評価対象外 | この音・単語は対応していない。聴き比べを案内 |
| 判定不能 | 対応対象だが確信が足りない。正誤を付けない |
| 対象の一致 | 検証済みの対象特徴が一致。評価していない特徴まで正しいとは扱わない |
| 改善候補あり | 根拠を持つ特徴だけ、短い助言を提示 |
| 通信・利用上限 | 学習を続け、保護者画面に理由を記録 |

評価エンジン、モデル、教材、助言テンプレートにバージョンを付ける。別の評価方式の数値をそのまま比較して「上達」と表示しない。

### 8.5 評価方式の切り替え

| 保護者設定・接続状態 | 利用する経路 |
| --- | --- |
| オンライン評価が無効 | 常に端末内の対応対象を評価。対象外は聴き比べ |
| オンライン評価が有効だが通信不可 | 端末内の対応対象を評価。後日送信する録音はためない |
| 有効・通信可能・利用枠あり・対象に対応 | オンラインで詳しく評価。子どもに同じ録音を再度要求しない |
| 有効だが対象外・利用上限・障害・待機期限超過 | 利用可能な端末内評価または聴き比べで継続 |

画面では「このタブレットでチェック」「ネットでくわしくチェック」「お手本とききくらべ」を短い表示で区別する。通信可否の表示だけで外部送信を有効にしない。

## 9. 冒険・動物・お世話

- 舞台は乗り物で巡る10の島。通常は一本道で進み、解放済みの島へは戻れる。
- レッスンの物語は「橋を直す」「荷物を届ける」など短いものとし、長い会話や動画で学習開始を待たせない。
- 初回に同行する動物を1匹選ぶ。島を完了するごとに1匹が仲間になり、初期版では合計11匹を用意する。
- 既に仲間になった動物から同行相手を選ぶ。動物による学力上の有利・不利は設けない。
- 初回完了時にレッスンスターを付ける。再プレイでも練習を褒め、ごはんを得られる。スターは習熟度とは別に扱う。
- ごはんはレッスン完了で1つ得る。任意で食べさせる・なでる動作ができる。初期版のお世話はこの2操作に絞る。
- 連続学習日数は保護者画面で参考として表示できるが、途切れても報酬を奪わない。
- 動物は利用しない間に弱らず、死亡・離別しない。ごはんは進級の必須消費資源にしない。
- 報酬に広告視聴、ガチャ、課金、外部共有を結び付けない。初期版に乗り物の収集・基地の装飾は含めない。

6歳にも分かり、9歳にも過度に幼く感じられない、明るい探検・図鑑調の表現とする。動物のセリフは短くし、音声案内を繰り返し聴くかどうかを子どもが選べる。

## 10. 音声・画像・教材制作

- 必須の教材音声、案内、イラスト、IPA表示用フォント、口の図は、インストール後にネットなしで利用できるよう同梱する。
- 学習音声は音素、単語、案内に分けて管理する。短文の型は将来拡張できるが、初期版の収録義務にはしない。
- 音声は自然な米語とし、単独音はフォニックス教材としての適切さを確認する。音声合成は候補にできるが、商用利用・保存・配布条件と実際の発音品質を確認してから使う。
- 音源を辞書サイトや動画から無断取得しない。APIの利用権がオフライン音源の再配布権を含むとは扱わない。
- 台帳に、素材ID、作成者、出典、ライセンス、アプリ組み込み・再配布・加工・商用利用の可否、クレジット、確認日を記録する。条件不明な素材を製品素材として採用しない。
- 音源と教材は音量差、クリッピング、無音、切れ、不要な母音、単語とIPAの一致を確認する。ゆっくり再生後も確認する。
- 新規の素材は差し替え可能にする。アプリの処理に直接埋め込んだ教材説明や音声パスの散在を避ける。
- 家庭版でも権利条件を確認する。一般公開前には米語発音と児童英語指導に知見のある人による教材レビューを必須にする。

## 11. 学習データ・録音・プライバシー

### 11.1 端末内に保存するもの

ニックネーム、設定、診断結果、開始地点、レッスン進行、独力での初回正誤、ヒント利用、苦手技能、復習予定、練習済み単語、学習日時・時間、スター、仲間・同行動物、ごはんの数を保存する。

録音の回数や「チェックを使った」履歴は保存できるが、音声を自動で永久保存しない。発音の推定結果は他の正答率と分け、評価できない回を誤答に含めない。

### 11.2 録音のライフサイクル

- 録音は初期状態では一時データとする。聴き比べに必要な間だけ保持し、レッスン終了・取消時に削除する。
- 異常終了時の一時ファイルは次回起動時に削除する。ファイル名に本名などを含めない。
- 残したい録音だけ「保存する」を選び、端末内のアプリ専用領域に保存する。共有や自動アップロードはしない。
- 保存録音は初期上限20件・各10秒までとする。上限に達したら保護者画面で整理でき、本人が保存した録音を無断で置き換えない。
- 録音一覧と全削除を保護者画面に設ける。録音を削除しても学習進行は消さない。
- OSの自動バックアップなどで録音が意図せず外部へ出ない設定を検討・検証する。オンライン評価を無効にしたときに音声が送信されないことを通信計測で確認する。

### 11.3 オンライン評価の条件

- 初期状態は無効。保護者ゲートの内側で、送信する情報、送信先、目的、保存期間、学習利用の有無、費用、停止方法を示して有効にする。
- 音声のモデル学習・広告への利用は認めない条件を採用する。録音の永続保存を行わず、処理後に破棄する条件を第一条件とする。
- 事業者側で処理中・障害時に保持されるデータの有無、期間、削除条件も確認し、処理後即時消去を契約で確認できない場合にそう表示しない。
- 条件が合う提供者が見つからない場合は、オンライン機能の採用条件未達として扱う。保護者の設定を超えるデータ利用を代替案にしない。
- 送るのは短い録音、対象の音・単語のID、評価に必要な言語情報など最小限。ニックネーム、正確な年齢、学校、位置情報、端末内の他の録音は送らない。
- 生の録音、録音を復元できるデータ、自由発話の文字起こしをアクセスログ・障害ログへ記録しない。
- 保護者が無効にしたら新規送信を停止する。進行中の送信は中止を試み、既に送られたデータを取り消せるとは表示しない。
- オフラインで録った音声を、後で接続しただけで送信するキューは作らない。保存録音も自動送信しない。
- 子どもが録音しない間にバックグラウンドでマイクを動かさない。

保護者ゲートは誤操作防止であり、保護者の法的同意を自動的に証明するものではない。一般公開時は対象年齢、国、配布ストアに応じた同意・プライバシー手続を別途満たす。

## 12. 保護者画面と費用制御

- 初回設定で保護者用PINを設定し、オンライン設定、録音一覧、データ削除、外部リンクを保護する。子どもにPINを読ませる音声案内はしない。
- PINを平文保存・ログ出力せず、照合用データを適切に保護する。連続した誤入力には待ち時間を設ける。
- 家庭版でPINを忘れた場合の復旧方法と、その方法で学習データが消える可能性を事前に説明する。固定の共通解除コードは用意しない。
- 学習履歴、文字と音の各技能、苦手、復習予定、開始地点、BGM等の音量、IPA表示、マイク、オンライン評価の設定を提供する。
- 2台の履歴はそれぞれの端末で確認する。クラウドの保護者ダッシュボードは初期版に作らない。
- 「録音だけ削除」「学習進行を初期化」「すべての端末内データを削除」を分ける。すべての削除では接続用情報も除き、再登録が必要になることを伝える。
- オンライン利用量、上限到達、接続不能、判定対象外などの理由を表示する。子ども向け画面で契約や購入を促さない。

オンライン評価は、初期値として1端末1日10件まで、2端末合計で月1,000円相当の利用予算とする。再挑戦も1件に数える。日次・月次の区切りは日本時間とし、バックエンド側で判定する。予算を変更できる操作は保護者・運用者に限る。

採用時に最新の最低料金、課金単位、リトライの扱い、税、為替を調べ、固定費を含む見込み費用が予算を超える場合は機能を有効にしない。従量費用は呼び出し前に保守的に予約し、上限に達したら新規評価を止める。単なる画面上の回数制限で予算を守ったと扱わない。

予算内で成立するサービスが見つからなければ、金額か評価頻度の変更が必要な設計課題として記録する。有料契約は別の導入段階で行い、要件定義中には行わない。

## 13. 技術方針と構成

Flutter/Dartを第一選択とする。初期ターゲットはFireのAndroid互換環境とし、両端末で音声再生・録音・モデル実行を検証してから本実装へ進む。Flutterの採用だけでiOSやすべてのFireの動作を保証しない。

- UI、学習・復習・報酬のロジック、教材、音声再生、録音、端末内評価、オンライン評価を分離する。
- 保存は構造化されたローカルDBを基本とし、教材はJSON等のバージョン付きデータ、音声・画像は資産として管理する。
- 音声再生・録音・モデルのライブラリはFireで動作するものを選び、Googleの音声サービスへ暗黙に依存しない。
- 評価機能は共通の結果形式を返し、UIに外部サービス固有の生の数値やエラーを出さない。
- オンライン評価は、アプリ→認証・上限管理を行うバックエンド→評価サービスの構成を基本とする。
- 提供者のAPIキーをAPK、教材、リポジトリに埋め込まない。バックエンドで管理し、端末には失効可能な限定権限の接続情報だけを持たせる。
- 家庭版では保護者が端末を登録する。子どものアカウントは不要。公開版の不正利用対策・登録方式は、Fireで使える手段を別途検証する。
- 通信はTLSで検証し、証明書検証を無効にしない。ローカル評価のために録音を外部へ出さない。
- 学習結果と進行・報酬は一貫して保存し、再起動や連打で二重報酬・進行消失を起こさない。
- アップデート時に既存の進行を移行し、教材IDが変わった場合の対応を定義する。

主要なデータ単位は次のとおりとする。

| 単位 | 主な情報 |
| --- | --- |
| Sound | 音ID、米語IPA、音源、口の図、説明、許容差 |
| Grapheme | 綴り、対応音、文脈条件、例外、導入順 |
| Word | 綴り、音・綴りの分解、意味、画像、音源、必要技能、確認専用フラグ |
| Lesson / Question | 前提技能、出題、許容解、誤答解説、報酬 |
| Attempt / Progress | 初回解答、ヒント、スキップ、技能別履歴、復習予定 |
| PronunciationTarget / Result | 評価対象、対応エンジン、バージョン、評価した特徴、確信度、結果状態、助言ID |
| Recording | 一時・保存の区分、作成時刻、端末内ファイル参照、削除状態 |
| Companion / Inventory | 仲間、同行相手、ごはん、完了スター |
| Settings / Consent | PIN関連情報、音量、マイク、オンラインの説明版・有効化日時 |
| AssetLicense | 出典、利用条件、再配布条件、クレジット、確認履歴 |

WindowsでFlutter/Android開発を行う。iOSへの正式展開ではmacOS、Xcode、署名、実機確認が別途必要になる。開発環境やライブラリの具体的なバージョンは互換性検証後に固定し、本書作成時点で導入済みとは扱わない。

## 14. 非機能要件

次の数値は実測結果ではなく、実機検証で確認する初期の目標値である。

| 項目 | 目標・条件 |
| --- | --- |
| 起動 | 初回準備・OS許可画面を除き、通常のホーム表示まで3秒以内を目標 |
| 教材音声 | 準備済み素材のタップから再生開始まで通常300ms以内を目標 |
| 端末内評価 | 5秒以内の録音について終了後3秒以内を目標。待機中も操作を停止しない |
| オンライン待機 | 8秒を上限に学習を続けられる状態へ戻す |
| 保存容量 | アプリ・必須教材・端末内評価モデルを合わせて1GB以内を目標。実測して配布方式を確認 |
| オフライン | 初回インストール完了後、必須教材・案内・図鑑・進行・お世話・録音・対応対象の端末内評価を機内モードで利用可能 |
| 音声競合 | 二重再生、BGMの録音混入、お手本音声の録音混入を防ぐ |
| 中断復帰 | 画面ロック・バックグラウンドで録音を止め、復帰時に継続方法を示す |
| データ耐久性 | 強制終了・再起動後も完了済み進行が保持され、一時録音が残り続けない |
| 電池・発熱 | 両端末で20分連続試用し、学習を妨げる停止・著しい遅延・温度警告がないか確認 |

音声モデルのサイズ、処理速度、メモリ使用量が条件を満たさない場合、範囲を限定する方式などを再検討する。要求された発音チェック自体を黙って削除して目標達成としない。

## 15. 検証・受入条件

### 15.1 発音評価の技術検証

教材・画面の量産より先に行う。両実機で、単独の/s/・/ʃ/と、対応する短い単語を最初の検証対象にする。他の対象は同じ基準で追加する。

- 評価用音声は、適切な発音、狙った音の置き換え、省略、付加、無音、生活雑音を含む。
- 子どもの声を含む、利用許諾・同意を確認したデータを用いる。評価用データを家庭版アプリに同梱しない。
- 音声の正解ラベルは発音に知見のある人が確認する。実際には適切な米語の変異を誤りに含めない。
- 学習・閾値調整と最終評価を話者単位で分離する。家族の2人だけでモデル精度を算出しない。
- 初期の合格目標は、対象ごとに、少なくとも子ども10人分・適切例50件と狙った誤り50件を用意し、単独音と単語、年齢帯ごとの結果を分けて確認することとする。
- 保留を許容した上で、適切例に誤った修正助言を出す割合を5%以下、助言を出した誤りについての指摘適合率を90%以上、有効な発話で判定を返せる割合を70%以上とする。件数・母数・保留率も併記し、この小規模結果を一般化しない。
- 無音や雑音だけの入力へ発音成功を返さないことを独立に確認する。
- 数値は本書で定めたリリース基準であり、既存手法が達成済みという意味ではない。満たさない対象には自動助言を出さない。
- オンラインの単独音と具体的な修正助言も独立に評価する。外部APIの宣伝上の対応言語や精度だけで採用しない。

データの確保、ライセンス、児童音声の評価、モデル、外部サービス、費用が検証上の前提となる。前提が満たせない場合は評価機能を検証済みとせず、要件未達を記録する。

| ID | 検証対象 | 合格条件 |

| AC-01 | 両端末 | インストール・起動・70レッスン分の教材読込・主要操作が実行できる |
| AC-02 | 学習内容 | 10島の必須範囲、120語以上、確認専用30語以上がそろい、前提技能と出題が一致する |
| AC-03 | 教材整合性 | 綴り・音源・IPA・口の説明・正解・許容解を照合し、欠損資産や不正な参照がない |

| AC-05 | 学習時間 | 両児童で導入・中盤・終盤から各2回以上試し、通常レッスンの過半数を3〜5分で完了できる。任意の反復・お世話は別計測 |

| AC-09 | 端末内評価 | 単独音と短い単語で、少なくとも1種類の音の対立が15.1の基準を満たし、両端末で動作する |
| AC-10 | オンライン評価 | 同意後のみ送信し、単独音・短い単語の検証済み対象で根拠のある助言を提示する。通信切断・期限超過・利用上限で安全に戻れる |

自動テストは採点・許容解、学習順序、復習、履歴、報酬の重複防止、教材参照、評価結果の扱い、同意と送信制御、削除に重点を置く。マイク・音声・発音評価・レイアウト・中断復帰は実機試験も行う。音声・IPAの内容は自動テストだけで正確と判定しない。

初期版完成は、必要な検証が実行され、未達要件・検証済み範囲が報告され、必須の受入条件を満たしたときに宣言する。未検証、失敗、対象外、スキップ、合格を区別する。

## 16. 開発・公開の段階

| 段階 | 成果物・次へ進む条件 |
| --- | --- |
| 0：実現性確認 | Fire両実機の再生・録音、限定的な端末内評価、単独音のオンライン評価、児童音声への精度、素材権利、予算を検証。未達の場合は仕様変更の必要箇所を具体化する |
| 1：小さな動作検証版 | 島1相当の教材と、復習→学習→発話→報酬→保存の一連の体験を作り、2人で試す |
| 2：家庭向け初期版 | 10島・70レッスン、図鑑、動物、お世話、保護者画面、両評価方式、必須受入条件をそろえる |
| 3：家庭試用 | 2〜4週間を目安に、操作性、時間、誤判定、苦手、初見語への転移を確認し、教材・導線を調整する |
| 4：一般公開準備 | 教材監修、対象年齢と配布国、プライバシー、保護者同意、データ処理条件、ストア要件、配布・更新・運用費を確認する |
| 5：拡張 | 例外語・rの影響を受ける母音・短文音読、他OS、同期、必要なら課金を追加する |

一般公開時はFire向けの配布方法と対応するAndroidストアを選び、現行の児童向けポリシーを確認する。買い切りで教材を提供する案を基本にするが、継続費用のあるオンライン評価を無期限・無制限に含めない。公開版での料金は運用費の確認後に定義し、家庭版に購入機能を先行実装しない。
